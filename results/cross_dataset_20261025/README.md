ETH配準研究及Liang公開處理版的外部提取驗證已完成；跨資料集配準仍缺少原始分站資料及真值，不能宣稱已證明配準泛化。

## 已完成

- 獨立兩站控制組118/150；10cm＋配準RANSAC為142/150。
- 六站最大生成樹為150/150，輸入條件與獨立兩站不同。
- 4項新增測試通過；圖路徑完整點誤差已對照C++；更換評分真值不影響估計變換。
- Liang / TreeTool：六樣區、三組固定ETH提取設定、seed11–20，共180次。18份有效設定檔與ETH逐位元組相同，全部偵測數與執行日誌一致。

## 建議

後續已完成新的兩站補救實驗：先用seed11–20設計並固定方案，再用seed21–30驗證。上一輪推薦組142/150，加三維一致性補救後150/150，補回8次、退步0次；兩組都只使用當前兩站。這是我們新增方法、依原先成功門檻的結果，仍非論文嚴格重現或跨森林泛化。最新精簡表與完整說明見 [後續研究](../eth_trees/failure_followup_20261025/report.md)；本目錄的試算表保留上一輪結果。

ETH獨立兩站優先採用匹配閾值10cm＋配準RANSAC；六站圖路徑另作多站任務。放寬verticality到0.85在ETH及外部處理版均沒有改善；暫保留0.90。

外部六樣區等權的參考樹匹配比例：control 38.34%、vertical085 34.94%、ransac999 38.52%；論文指定Plot1/3/5則為43.80%、39.48%、44.10%。增加圓柱擬合資源只有小幅差異，尚不足以支持取代控制組。這些是提取覆蓋指標，不能與ETH配準成功率混用；沒有計算標註範圍不明的precision/F1。

後續優先取得另一份原始分站點雲及配準真值，以固定10cm＋配準RANSAC評估。提取方面先檢查漏失參考樹的地形、遮擋與圓柱拒絕原因，並確認掃描中心及參考座標定義，再決定是否改動提取流程；目前處理版的感測器原點與標註範圍尚未獨立核實。

## 試算表

comparison_simple.xlsx為三張表的精簡版：調參重點、ETH各配對改善、Liang各樣區變化。首頁直接說明改動、變好或變壞及保留建議；與完整版使用同一份結果。重建：`python3 scripts/eth_trees/make_simple_workbook.py`，只需要openpyxl及已保存的完整版/摘要CSV，不需重跑實驗。

comparison.xlsx採白底、灰色表頭、凍結表頭、篩選和統一數字格式；未取得配準資料顯示「未執行／待取得資料」，不是0%。包含1950筆ETH逐對結果、每seed、方法參數、共同成功案例精度、篩選紀錄、GT獨立性核對，以及180次外部提取結果、逐樣區摘要、論文子集比較、來源版本與限制。

重建：先執行scripts/eth_trees/make_study_workbook.py，再用LibreOffice Calc將runs/input/comparison.xlsx重算輸出到本目錄。只在取得並核驗新資料、完成同參數測試後，才將datasets.json對應列改為available並加入結果路徑。
